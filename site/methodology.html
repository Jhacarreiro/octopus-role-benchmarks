Role quality and portfolio modes

The detailed ranking table exposes role-quality signals and cost-per-quality values. The eight recommendation cards are generated separately as constrained portfolios: Quality, Balanced and Budget.

QualityIntelligence floor 0.90 → adaptive ≥5-family pool → maximize total Role Quality
BalancedIntelligence floor 0.85 → remove plan-adjusted cost > mean + 2σ → maximize total Role Quality
BudgetIntelligence floor 0.80 → maximize included monthly plan capacity

When an initial Intelligence floor leaves fewer than five candidate families, the floor is lowered in 0.005 steps until five families are available. Every final lineup still requires at least four families and allows at most two seats per family.

There are no mandatory models, manual Fable blacklist, or per-role quality floor. Code Reviewer must differ from both implementation identities. Implementer Heavy must differ from Implementer and must have at least +2.0 AA Intelligence Index points.

Security Reviewer

Security Reviewer = Vals AI CyberBench Overall, directly. The previous SciCode/GPQA/HLE/Omniscience/LCR proxy has been removed. If a model has no direct CyberBench score, it is simply ineligible for this one role.

Balanced uses plan-adjusted cost only as an outlier filter. Once expensive outliers are removed, price no longer affects its role-quality optimization. Budget instead optimizes how many complete portfolios fit inside the separate standard and premium Max monthly allowances.

CommandCode credit burn and plan-adjusted Cost per Task

Price per million tokens is not used as the primary denominator. Artificial Analysis measures the token mix consumed per Intelligence Index task. Those measured non-cached input, cache-read, cache-write and output tokens are repriced with the current effective CommandCode Max rates.

task cost = input tokens × CC input + cache-read × CC cache-read + cache-write × CC cache-write + output × CC output

If CommandCode exposes no separate cache rate, normal input price is used. Active CommandCode promotions are retained.

CAI*: observed when possible, estimated otherwise

For missing Coding Agent Index values, the estimate is deliberately simple:

CAI* = 50% Ridge prediction + 50% inverse-distance 5NN prediction

Ridge (λ=1) uses SciCode, GPQA, HLE, LCR, GDPval, AA-Omniscience Index (normalized to 0–100) and log(Output Tokens/Task). 5NN uses SciCode, GPQA, HLE and LCR, standardized across the observed CAI training set, with Euclidean distance and inverse-distance weighting over the five nearest models.

The estimator is trained only on unique model families with observed AA Coding Agent results. Commercial CommandCode variants never count as extra training examples.

Coverage and failure rules

Universal weighted-role components, CommandCode Cost per Task and final CAI* must cover the scored model-family universe according to the published coverage rules. Security Reviewer is role-specific and uses direct CyberBench coverage instead. Stealth/unresolved rows remain visible as UNSCORED. Validation continues to fail closed when estimator/ranking guardrails are breached.

Raw model mappings, observed/estimated CAI*, Ridge/5NN components, role scores, task costs and final Ranking Values are all preserved in the public JSON snapshot.

Portfolio regeneration

After refreshes, Octopus regenerates the complete Quality, Balanced and Budget portfolios under the current deterministic policy. Review data records portfolio-level changes rather than evaluating independent hand-picked seat swaps.

The policy file contains rules, not selected model names. Generated selections and their requested/effective Intelligence floors, family counts, costs and Balanced outlier statistics are published in site/data/lineups.json.
